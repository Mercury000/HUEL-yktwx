# 修改校园卡查询密码

核验日期：2026-10-22（Asia/Shanghai）。协议来源为本人官网页面的网络请求及前端源码；本轮实现只运行离线测试，不替用户提交真实修改请求。原始 Token、Cookie、账户、密码与键盘映射未写入仓库。

## 验证范围

- 已抓到官网 `modifyPwd` 请求及三个独立数字键盘会话，确认字段与编码格式。
- 官网源码确认成功判定为外层 `code=200` 且 `data.retcode="0"`。旧请求响应体已清理，未用 HTTP 200 推定成功。
- 用户实测反馈修改后登录会失效，并要求原生客户端成功 Toast 后返回登录页。因此客户端主动清除旧凭据与 Token，不按官网的普通返回上一页逻辑处理。
- 无 Cookie 的真实改密提交尚未验证；现有第一方传输仍不携带 Cookie。真实成功与错误响应需用户本地验证，不自动重试写请求。

## 接口

```http
POST /berserker-app/ykt/tsm/modifyPwd
Content-Type: application/json;charset=UTF-8
synjones-auth: bearer <access_token>
synAccessSource: h5
```

```json
{
  "account": "<selected campus-card account>",
  "oldpw": "1$1$<encoded old password>$1$<old keyboard uuid>",
  "newpw": "1$1$<encoded new password>$1$<new keyboard uuid>",
  "renewpw": "1$1$<encoded confirmation>$1$<confirmation keyboard uuid>",
  "synAccessSource": "h5"
}
```

`account` 来自 `getCampusCards` 的目标卡片统一账户，不是学号；无 `pwdType` 字段。只接入当前观察到的 6 位数字、原密码校验路径，不接入短信、证件号重置、免原密码或复杂密码分支。提交前重读配置与卡状态，不对冻结或异常卡操作。

## 编码与输入

- 原密码、新密码、确认密码均为 6 位数字；新密码与确认密码在明文输入阶段校验一致，不比较两次编码串。
- 三个字段分别获取一次 `GET /berserker-secure/keyboard?type=Number&order=0&synAccessSource=h5`，使用同次 `numberKeyboard` 与 `uuid`。
- 官网本次使用 `order=1` 的乱序图像键盘；原生使用既有固定顺序编码器要求的 `order=0`，不能把乱序键盘索引当作数字。
- 输入掩码展示，只用 `remember`，不进入 SavedState、日志或持久化；提交、取消、切换卡片和重新打开均清空输入。预览不发送写请求。

## 成功、失败与登录

- 仅确认 `code=200`、`data.retcode="0"`，且不存在矛盾的失败标志或账户回显冲突时认定成功。
- 确认成功后，在共享会话锁内清除旧登录凭据与 Token，防止等待中的付款码刷新用旧密码自动重新登录。
- 根页面收到成功事件后，Toast 提示“查询密码修改成功，请重新登录”，停止付款码任务并返回登录页；账单、充值与校园卡页面跟随账户切换清理。
- 失败在弹窗固定错误槽直接显示服务端原始消息，不添加“修改失败：”前缀或其他包装，也不额外添加“请重试”。外层拒绝原样使用 `msg`；内层拒绝原样使用 `data.errmsg`（缺少时回退至服务端 `msg`），不 trim、不改写或通过文案猜测结果。认证拒绝同样保留实际改密响应的原始消息。
- 失败保留弹窗与选中卡片，不清除已有凭据；改密写请求认证拒绝时不自动重登录或重发。
- 超时、断网、缺少结果等无法确认的情况没有可用服务端消息时，才使用本地“修改结果未确认”提示；不误报成功、不自动重试、不自动尝试旧/新密码验证。

## 2026-10-22 数字键盘映射异常排查

仅通过无登录、无写操作的数字键盘 GET 请求抽样检查字段特征；40 次有效响应中，2 次合法映射含 `$`，长度均为 10 且字符唯一。未保存映射、UUID 或图像。旧 `NumberKeyboardEncoder` 把映射中的 `$` 视为非法，导致原生在提交前误报“数字安全键盘映射异常”；这与是否第一次登录无关，是随机映射内容触发的本地误拒绝。

官网组件直接将 `numberKeyboard[index]` 加入编码密码，再拼接 UUID 后缀，没有过滤或转义映射中的 `$`。现移除映射字符 `$` 禁止项，保留长度、字符唯一性、控制字符及 UUID 检查；不重取键盘碰运气、不重放写请求。由于共享编码器同时用于解挂，本修正同时适用于解挂与改密。离线测试覆盖 `$` 的全部 10 个位置、编码内容形似分隔符、三个改密字段各自在首次键盘中出现 `$`，并确认每次只有三个键盘请求及一次改密写请求。

改密弹窗不显示成功后退出登录的提前说明；确认成功时仍保留 Toast 与返回登录页流程。
