# 大厅电表、水表配对

2026-10-26 使用 MCP 登录学校官网后，以实际查询返回核对文北和家属区。
这里只记录协议结构与规则，不保存会话凭证、个人住址、账户 ID 或原始响应。

## 实际观察

- 桌面 Chrome UA 点击文北入口后，`/charge/feeitem/toAppitem` 跳转到 PC 的“未授权”页面；Android Chrome UA 可进入 `/charge-app/#/pays?id=409`。这次结果只能证明该入口在当前会话存在 UA 差异。
- 文北照明与空调位于不同的楼栋分支，不能复用楼栋、楼层、房间 ID。7 号楼空调分支的房间名前缀实际为 `77-`，对应照明前缀为 `7-`；充值摘要保留官方房间名，不把前缀改成客户端推测的名称。
- 旧 HAR 中 5 号楼空调“二层”返回 `5-1xx空调`，照明“二层”返回 `5-2xx照明`；本次实时复查这两个分支均返回 `5-2xx`。应读取当前选项，不把旧房间列表或楼层关系写死在客户端。
- 家属区电费 448、水费 449 都返回 `xiaoqu_id → loudong_id → louceng_id → room_id`。从一个电费绑定逐级查询水费，能找到校区、楼栋、单元、户号均相同的水表；两个项目保留各自完整的选项 value。
- 家属区电费的 `showData` 返回“剩余电量(度)”，水费返回“剩余水量(吨)”。本次查询没有返回水费余额金额。配置的 `billing_unit=元` 指付款金额，不能把吨换成元，也不能把 `allAmp/usedAmp` 当作金额。
- 官网恢复文北绑定时自动发出过一次仅含 `feeitemid` 的 `sceneBind/add`，导致解绑。经用户同意已原样恢复并回读确认。客户端查询和配对不调用绑定接口。

## 实现边界

`DormMeterDiscovery` 恢复当前绑定、读取表数据；`DormMeterPairing` 处理大厅已绑定房间的文北跨楼栋分支与家属区跨项目查询。临时缴费由 `FeeViewModel` 使用同一配对规则：选择器先按物理位置合并服务端 option，表计切换完成全部查询后再原子更新界面状态。

文北先在当前校区返回的楼栋选项中找到唯一的照明/空调对应分支，再查询该分支的楼层、房间选项。在这个已限定的楼栋内按房间编号配对，并检查整个分支是否唯一；同号重复或查询不能确认时，不返回推测的目标。每一层都使用该分支实际返回的 ID。

临时缴费中的文北楼栋和房间名称去除末尾表计类型后展示，照明／空调只通过房间下方按钮选择。切换期间保留原完整房间，目标分支的楼栋、楼层、房间和详情全部确认后一次提交到 UI；失败时继续使用原目标，避免出现逐级回填或半套 ID。

家属区逐级按完整位置名称配对，去除的只有水表/电表类型后缀。另一项目绑定了不同户时，仍查询当前户的对应表。合并按完整住址分组，不同户保持独立；每个表保留原项目、房间和查询数据，管理/解绑只针对真正的官方绑定。

临时缴费切换水／电同样采用原子更新：查询过程中位置下拉保持当前已确认内容，仅类型按钮显示目标项目；成功后一次替换配置、选项、选择值和详情，失败则完整恢复原项目状态。

绑定记录名称与当前列表不一致时，配对、分组和展示采用本次恢复选项后获得的名称；原绑定仍单独保留用于管理核验，不自动写回名称。

余额展示直接读取每个表的官方 `showData`。数量、单位和附加字段分别保留，未知文本原样展示；支付摘要保留官方房间名。

## 回归验证

测试覆盖单独绑定水表或电表后的“查询 → 合并 → 展示 → 充值目标选择”，不同住址不合并、重复房间不误配、楼层名称错位、空调房间前缀不同及水量不冒充金额。测试使用虚构房间和模拟接口，不执行真实下单或充值。

状态回归覆盖刷新过程中绑定变更后的再次读取、部分解绑后的真实绑定回读和错误保留、旧房间卡片不能解绑已变更的绑定、切换账号后丢弃旧响应，以及取消后迟到的订单不能恢复支付界面或拉起微信。绑定失败停留在选房页，绑定结果未知时禁止继续提交绑定。

大厅一卡通密码页复用原有 `FeePasswordDialog`，金额及可用余额保持居中。原生 Compose 截图和测试验证无重复充值面板、密码提交后清空、错误后需要重新输入，以及取消返回金额页。

订单渠道以服务器实际列表为准。预选渠道缺失时，显示与确认使用同一实际渠道；只有用户点击确认后才准备支付。同一渠道代码下的不同 ID 也按用户选中的 ID 处理。

2026-10-26 本轮全量单元与原生 Compose 回归测试通过 402 项，零失败、错误或跳过；Debug、Preview 安装包均构建成功。随后移除代人充值“重新查询”按钮，相关 UI 回归 16 项与两种安装包构建再次通过。验证未执行真实下单或充值。
