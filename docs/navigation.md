# 页面导航与转场

页面导航使用 `miuix-nav-android:0.9.4-3a980f7c-SNAPSHOT` 的 `NavDisplay`。主题设置中的“转场风格”提供与 demo 相同的 **Miuix / AOSP** 选择，默认 Miuix，选择后立即生效并保存在本机。

## Miuix

- 普通进入与返回使用库默认的 500ms 曲线。进入页从末端滑入整页宽度，被覆盖页向起始方向移动 ¼ 页宽，透明度最多降低 10%；RTL 布局镜像。
- 使用 demo 默认的前缘圆角裁剪和最大 0.5 调暗，圆角半径跟随设备屏幕；过渡期间不额外启用全局输入拦截。

## AOSP

使用 demo 的 `CrossActivityTransition`，仅调整 Kotlin 包名，保留原实现及 Apache-2.0 版权声明。

- 普通进入与返回使用 450ms 曲线，两层页面平移 96dp；进入页和退出页有独立的 83ms 淡入、淡出时间轨道，无缩放和调暗。
- 系统预测返回和页面滑动返回采用卡片缩放，最小约 90%，四角裁剪、纵向跟手和速度相关回弹均沿用 demo。取消恢复原位，确认后卡片飞出并淡出。
- 手势调暗强度为浅色 0.2、深色 0.8；缺少屏幕圆角或在宽屏区域内时使用 demo 的 32dp 备用圆角。

## 共用导航行为

- 系统预测返回由库处理，没有独立开关。Miuix 共用普通转场的页面变换；AOSP 通过 demo 的方向转场组合区分普通进出和手势返回。
- “启用滑动返回”沿用 demo 的可选页面滑动返回，默认关闭。它控制页面内的滑动手势，不关闭系统预测返回；方向随 LTR / RTL 布局变化。
- 付款页底栏和服务进度胶囊岛位于同一主页面内，覆盖和返回时跟随页面转场，不单独播放上下升降动画。
- 宽屏普通侧栏位于 `NavDisplay` 外部，保持固定。OS4 的 `GlassNavigationRail` 同样在导航区域外层持久挂载，覆盖页面并采样不包含自身的背景。导航区域裁剪越界图层；宽屏 Miuix 转场不使用屏幕圆角，AOSP 使用备用圆角，iOS 底栏布局也按实际窗口尺寸判断转场圆角。
- 点击侧栏先清空二级页面栈、返回主页面，再切换标签；点击当前标签同样返回主页面。
- 自适应布局沿用 demo：宽度达到 840dp，或宽度达到 600dp 且高宽比小于 1.2 时进入宽屏布局；默认样式使用普通侧栏，OS4 使用玻璃侧栏，iOS 保留原底部悬浮导航。宽度达到 1200dp 时侧栏默认展开，窗口缩小时自动折叠。侧栏仍可手动展开或折叠，跨越宽度阈值时重新按窗口尺寸调整，旧展开偏好不再覆盖自适应规则。
- OS4 侧栏收起时是顶部居中的文字胶囊，展开为左侧图标与文字面板。展开进度在布局和绘制阶段驱动页面起始侧留白与顶栏标题透明度；宽屏顶栏采用官方不可展开布局，按钮继续按实际滚动显示玻璃。安全区包含系统栏、窗口标题栏和屏幕缺口。
- 平板普通及 OS4 侧栏布局下，扫一扫仅在付款页顶栏右侧显示；OS4 顶部标签与展开面板共用这个入口。iOS 继续在付款页悬浮底栏右侧显示扫一扫，其他标签不显示。
- “导航样式”始终显示默认 / iOS / OS4，选择 iOS 或 OS4 会启用对应悬浮导航；原有普通与默认悬浮偏好仍保留。导航模糊始终可设置，控制当前底栏、玻璃侧栏及服务进度小岛；官方普通侧栏保持实色。玻璃风格和顶栏模糊保持独立。
- 导航区域和主页面内容保持同一组合位置，窗口尺寸、导航样式及侧栏展开状态变化不重建当前页面或重置滚动状态。iOS 底栏仍属于主页面，二级页面返回时随主页面恢复；OS4 和普通侧栏则保持挂载，点击标签先返回主页面再切换。

原有 `IslandNav`、三层限制、背景缩放和模糊、返回距离设置、独立底部导航升降动画已移除。旧预测返回设置不再读取。顶栏和底栏的模糊设置继续控制各自的背景。

页面栈使用 miuix 的 `NavBackStack`，由 `AppNavigationViewModel` 结合 `SavedStateHandle` 按账户范围保存。路由只包含可序列化的页面标识和恢复所需的参数，重复打开同一个路由时不重复入栈；业务模型、登录凭据和支付数据不写入导航状态。窗口尺寸与侧栏样式变化不会替换导航栈。

主标签页沿用 `HorizontalPager`，内容顶部对齐，不扩大屏幕外页面范围，也不进行自定义预热或保留全部标签页。点击标签使用库的 `springAnimateToPage`，手势切页使用同一弹簧参数；按官方示例配置 CrossAxis 接管、共享 fling 和 `PagerGestureNestedScrollConnection`，支持列表仍在滑行时横向切页。导航深度与 Miuix / AOSP 转场使用原实现，业务读取与付款传感器仍按现有活跃状态控制。

登录边界也跟随所选风格，以单个路由替换展示当前登录状态。应用级服务模型继续由原来的 ViewModel owner 管理，退出期间仍按当前登录状态清除付款内容并禁用旧页面操作。
