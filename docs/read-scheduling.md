# 展示读取调度

付款、大厅、账单、“我的”、个人信息和账户详情共用读取环境与请求生命周期。页面仍决定读取范围、结果展示和缓存新鲜度；调度器集中处理许可、同查询并发、普通网络重试及完成后的再次判断。

## 职责

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| `AndroidNetworkMonitor` | 默认网络监听、连接快照、连接世代 | 请求、页面可见性 |
| `YktApp` | 合成并发布 `ReadEnvironment` | 页面内查询与重试计时器 |
| `ReadGate` | 许可判断、实际尝试记录、失败预算 | 协程与业务结果 |
| `ReadController` | 请求预留、网络租约、取消、普通退避、待执行操作 | 查询新鲜度、交易结果 |
| ViewModel | 查询键、本地准备、读取范围、结果版本、错误及展示 | 普通重试与重连等待任务 |
| `TransactionRefresh` | 按接口比较交易前后快照、有限补查 | 支付是否成功、普通网络恢复 |

生产 ViewModel 从 `ReadEnvironment.Inactive` 开始，在界面壳发布快照之前不启动展示读取。注入依赖的测试构造器可以显式提供独立环境。预览使用虚构资料，不注册真实网络监听。

`ReadEnvironment` 一次携带可读取页面、前台状态、在线状态、连接世代、前台恢复序号，以及付款／账户展示状态。`online = null` 表示尚未确定，允许尝试读取；明确离线时阻止新请求。连接世代只由网络监听器推进，离线恢复或默认网络变化会增加世代，回前台只增加恢复序号。监听状态由 `NetworkStateViewModel` 保留，Activity 重建后与页面 ViewModel 的世代保持一致；界面壳挂载时监听、卸载时注销，回到前台重新核对连接快照。付款码能否保留在覆盖层后继续倒计时与页面能否发起新请求分别判断。

## 请求生命周期

1. ViewModel 先通过 `canStart` 检查许可，再更新加载状态。
2. `launch` 同步预留查询，随后执行本地准备。重复自动触发复用当前请求，不重复准备。
3. 本地准备完成后，紧邻首个网络调用执行 `startNetwork`，再次检查当前环境并取得租约。只有此时记录实际尝试及其连接世代。
4. ViewModel 校验账号、查询及业务读取版本，接收结果并保存展示缓存。
5. 接收完整结果后调用 `complete`；协程结束时由控制器统一释放租约、安排普通退避和处理待执行操作。没有完成结果的退出按取消或跳过处理，不伪造网络失败。

请求预留包含本地准备和缓存保存，而不是只包含接口等待。这样慢本地准备跨越重连时仍只有一个逻辑读取。独立展示缓存任务不因网络任务取消而一起取消；账号或缓存目标变化时由 ViewModel 取消旧准备，并在接受结果前再次校验目标。

租约使用对象身份。取消或替换后，旧请求即使在不可取消的调用中迟到，也不能释放新请求的租约、安排旧重试或恢复旧账号任务。控制器全部在所属 ViewModel 调度线程调用；它不额外加锁，网络与磁盘工作继续使用已有 IO 路径。

## 查询与触发

`ReadQuery` 包含账号、资源及参数，避免拼接字符串产生身份歧义。付款、账户和转身检测各用独立资源；“我的”包含月份；账单明细包含日期、类型、金额及搜索条件，统计包含日期与收支方向，分页与第一页使用不同资源。分页序号仍由 ViewModel 的当前页状态管理，同一列表同时只允许一轮追加。查询键的日志输出隐藏账号与条件。

| 触发 | 普通自动重试 | 语义 |
| --- | --- | --- |
| `Initial`、`Visible`、`Reconnect`、`Retry` | 网络失败时允许 | 初读、激活、网络恢复及退避重试 |
| `Pull`、`Action` | 不额外排队 | 用户下拉、按钮操作及分页，开始时重置对应查询预算 |
| `Transaction` | 不额外排队 | 交易核对，由 `TransactionRefresh` 控制后续次数 |
| `Motion` | 不额外排队 | 付款转身检测，保留原有三次有限探测 |

公开付款 `refresh()` 的默认语义是用户操作；内部自动调用必须明确传入 `Visible` 等自动触发，避免把倒计时刷新当作用户操作无限重置失败预算。

自动重复触发合并到当前请求，成功结束后再次判断新鲜度；结果已经展示但缓存仍在保存时到期，也能继续读取。失败结果遵守恢复与退避规则，不因重叠触发立即重读。重连或前台恢复遇到在途工作时记录再次判断，等待当前工作结束后检查当前页面仍缺什么。用户操作由页面决定合并方式：可以保留最新操作并在当前工作结束后执行，也可以与当前读取合并。付款结果已经展示但旧请求仍在保存缓存时，新的明确刷新可替换旧请求，并同步进入加载状态。待执行操作在查询取消、账号重置、隐藏或离线时清除；完成与回调之间让出的调度间隙也受取消保护。

## 两类重试

普通网络失败：每个查询、每个连接世代最多连续失败两次。首轮自动读取失败后等待 600 毫秒补试一次；等待期间重复激活不能绕过退避。成功清空失败预算，正常成功的周期读取没有“两次后停读”的限制。认证和业务失败不启动网络重试计时器。明确用户操作重置查询预算，但其失败本身不追加自动请求。

重连：新世代重置失败预算，只处理当前选中的查询。旧世代请求结束后立即按新环境判断；本地准备跨越重连并在新世代开始网络请求时，该请求已经属于新世代，不再因同一个恢复通知重复读取。单独的恢复入口忽略旧世代和本世代已经开始过的恢复事件。

交易补查：初始读取后最多三次，间隔为 2、5、10 秒，只查询尚未观察到变化或读取失败的接口。存在待核对交易时，自动激活的首轮与后续补查都使用 `Transaction`，不叠加普通网络重试；重复交易触发与在途工作合并，不排队重放。隐藏、后台、覆盖或离线暂停定时补查，保留比较基线和已用次数；回页面不重新发放三次预算。详细规则见 [交易刷新](transaction-refresh.md)。

## 页面边界

- 付款离页或后台立即清除不可继续展示的付款码；覆盖层允许保留倒计时，到期仍清码。离线不把账户接口的在途结果直接丢弃，也不允许新取码。真实认证失败才要求重新登录，离线提示只属于界面状态。
- 大厅保留按项目并行读取、局部电表结果与绑定校验。读取期间发生绑定失效，完成后仍强制再核对一次，不能被本轮成功的新鲜时间覆盖。所有项目与电表的错误类别共同决定页面级失败，不能遗漏局部网络错误。
- 账单保留各查询缓存、分页、父子转场及滚动位置。切换查询取消旧网络请求和退避计时器，即使接口已经结束；旧查询的重试不能刷新新查询。恢复连接只核对当前明细或统计查询。
- “我的”保留个人资料与月度指标独立发布。月份变化取消旧月份读取，重新准备该月展示，避免旧金额进入新月份。个人信息详情共享资料读取，但独立失败的身份／头像仍参与恢复判断。

登录、充值、缴费、卡状态写操作及绑定管理继续使用各自的业务流程。展示调度器不重放这些操作。Repository 继续负责会话更新、账号身份与缓存写入隔离，页面的业务版本检查与控制器的任务身份检查分别保护结果与调度状态。

## 验证入口

`ReadControllerTest` 用虚拟时间覆盖准备与实际尝试、普通退避、成功后继续读取、重连与前台恢复、操作合并／替换、隐藏、取消间隙、迟到完成及交易触发。`ReadGateTest` 验证许可、预算、连接世代来源和租约身份。

四个 ViewModel 及交易／展示缓存的定向回归验证既有业务行为；网络监听、实际导航、离线收支切换与读取反馈检查壳和界面接入。测试使用虚构服务与 Robolectric，不连接真实校园卡或支付接口。
