# 哈啰单车接入

实现日期：2026-11-13。普通单车网络骑行与普通付款从 `feature/hellobike`（`aa42183`）线性接入当前迁移架构。服务、加密存储、定位和 ViewModel 由 Hilt 提供，共用应用 HTTP、扫码与付款设施。验证使用虚构账号、订单和离线响应；尚未验证真实账号、车辆或支付。

校园使用范围（2026-11-13）：按用户提供的使用条件，本次仅用于校内，车辆无法出校、无额外费用且没有蓝牙车。这些是本次接入的使用前提，不代表已核验平台所有车辆及收费规则。当前需求为普通网络开还车、正常骑行费结算及订单恢复／查询；调度费接受和蓝牙还车不列为当前接入要求，相关 REA 证据保留作后续参考。现有异常条件检查和异常场景的「打开哈啰」入口继续保留。

## 入口与共用界面

- 付款页共用「扫一扫」。`http(s)://c3x.me` 的明确 `n`／`u` 单车参数在本机解析，随后在现有 `Screen.LifeDevice` 中显示车辆、计费规则和操作；不访问二维码链接或跟随跳转。
- 扫码按域名确定平台、参数确定业务，拒绝伪造主机、重复参数、冲突车号和其他车型参数。手动入口统一填写设备编号，不接受链接；十位数字同时可能是骑行车号或798编号，用户选择设备上的平台后继续。相机扫描的裸数字不改判为哈啰。
- 识别后等待哈啰账号恢复；未登录时使用现有设备页内联提醒和共用登录抽屉。登录后继续检查原车辆，须再次主动确认计费并开锁。
- 复用设备页外壳、卡片、字段、底部操作栏、加载与错误提示、骑行参考计时和完成展示。接水与洗衣也使用提取后的共用信息、说明和进度组件。
- 开锁中、骑行中、还车中、结果未知、待付费及付款结果未知的订单保留付款页胶囊岛。结清或关闭后按798／胖乖用水的共享退出动画自动下岛；设备页仍可查看当前订单。
- 所有生活服务统一允许通过 × 删除异常或状态不明确的本地记录，包括状态查询失败、开关锁结果未知、费用及付款结果待确认。× 删除本地记录与展示，不发送还车、取消或付款请求；迟到响应不能重新插入已删除记录。明确正常的骑行中、待支付记录不显示 ×。
- 设置中的「生活服务账户」包含慧生活798、胖乖生活和哈啰。各平台显示自己的名称、服务范围、脱敏手机号和核验状态；登录提醒的关闭选择分别保存。
- 付款沿用共用支付方式和结果抽屉、支付宝及银联桥接。返回或关闭抽屉不会重新发起付款；退出动画中的按钮禁用。
- 预览不读取或改写哈啰保存数据，不获取位置，不发起哈啰请求。界面验证通过虚构快照展示各阶段，不操作真实业务。

## 登录与验证

登录抽屉复用胖乖生活和慧生活798的手机号、短信验证码及登录布局，不展示地区编码，也不要求用户先定位。点击「发送验证码」后，只有服务端要求拼图时才在同一抽屉切换到安全验证页；拖动松手或无障碍调整后提交验证。验证成功并确认发送后返回短信输入页、开始倒计时；没有第二个「验证并发送」按钮。刷新只换图，不另发短信；取消验证保留手机号，旧请求结果不能重开验证页。

短信、拼图和登录请求有有效缓存地区时附带，没有时省略，不编造默认地区。官方 7.0.75 原始 `classes8.dex` 中 `SendCodeV3Request` 三参数构造直接从 `LocationManager.s().n()/l()` 读取 cityCode/adCode；此构造没有先定位或要求填写地区的门槛。此次 REA 的 Evidence 为 `ev_6403ac956ac59631ec19f46197431b9bbf6a98d45354bf557cc5b1cbaba89ac8`，分析切片中的 DEX 与原 APK 逐字节相同。既有 `LoginAction` 构造依据见 `hellobike-integration-evidence.json`。这些静态证据不证明真实服务端接受缺失地区，仍须实际登录验证。

普通登录、骑行和付款不常驻显示外跳入口；哈啰明确要求额外验证、业务异常或无可用付款方式时才提供「打开哈啰」，骑行帮助中也可打开。骑行页只保留进度、车辆信息和一条操作提醒，具体还车位置检查留在「还车」操作后。

账号检查与骑行发现使用官方单车 `user.ride.bikeCheck`，按 `RidingOrderRepository.checkOrder` 读取 `data.ride.order`。普通业务非成功响应、空 data、空 ride 或空 order 均表示没有可恢复的骑行，账号继续显示已登录，不显示「检查失败／无骑行中订单」；HTTP／网络失败和官方登录失效码仍分别处理。移除原型 `user.tw.ride.check` 的 `rideInfo.rideStatus=-99` 推断，已有本地订单仍单独按原订单查询结果。具体静态依据与边界见[账号检查核验](hellobike-account-check-evidence.md)。普通账号恢复后自动检查。三项生活服务共用账号显示规则：本机已有登录凭据显示已登录，检查进行中显示检查中，失败显示检查失败及具体原因，明确过期显示登录失效，不再将失败折叠为待验证。退出弹窗统一为「退出后需重新登录。」。定位的数据用途归入统一隐私段落，继续以同一正文哈希控制阅读与同意，不建立哈啰专用同意说明。

## 定位与车辆操作

位置仅在应用前台的车辆检查和还车操作期间请求，登录与恢复骑行记录不请求定位。使用 Android 原生定位，允许系统精确或粗略位置授权，检查经纬度及数据格式有效后将 WGS84 转换为 GCJ-02 发送。不按自定的30秒、80米或模拟位置标记拒绝业务；位置是否可用由本次云端接口判断。

离开设备页停止设备检查、开关锁任务和相关定位；进入后台停止位置、认证、读单与轮询。系统权限返回通过请求标识关联原操作；离页、关闭登录或旧权限结果不能继续操作车辆。恢复位置授权只重做检查，不自动开锁。

地区编码由实时位置反查，界面不提供手填编码。反查失败后保留原车号或骑行记录，用户可重新检查；不能以历史地区代替本次车辆操作的位置。未新增后台定位、蓝牙或短信权限；清单仅增加前台定位和官方哈啰包可见性。

| 阶段 | 进入条件与后续行为 |
| --- | --- |
| 车辆检查 | 调官方 `user.ride.pre.ride`，普通响应按 `result=true` 或 `causeType=1100` 继续；显示完整官方提示和可选计费规则，不自设60秒有效期，不按本机已有骑行阻断新车检查。原订单从进度入口恢复与查询。 |
| 正在开锁 | 用户点击后，先可靠保存原订单和待提交状态，再发送一次创建请求；创建报错或响应丢失时查询原订单。查询确认为20/22或20/23时继续展示开锁进度并清除误报，不重发创建请求。重启恢复也查询原订单。 |
| 骑行中 | 显示参考计时。返回付款页、离开设备页或退出登录都不会还车。 |
| 还车位置通过 | 查询返回普通网络类型及可确认的官方causeType，由用户明确确认；不按费用字段或本机30秒期限追加拒绝。 |
| 正在还车 | 用户确认后先保存待提交状态，再发送一次关锁；仍查询到骑行中时继续保留关锁待确认，不重新开放关锁命令。 |

P10预还车使用 `causeType`：1101／1108继续位置查询，1102／1103允许正常网络还车确认，1100表示已还车并查询结束信息。`skipConfirm=false` 是官方正常确认分支。优先显示完整云端causeDesc；不把penaltyFree、penaltyDisplay、蓝牙密钥或附加费用的出现当作额外拒绝条件。明确非网络type仍属于未接入的控制方式。已经提交的请求遇到超时、取消或无法明确分类的错误时保留原记录，只继续查单，不自动重放。最新逐项证据与限制见[云端判断与原文提示核验](life-cloud-authority-audit.md)。

2026-11-13 的[调度费与蓝牙还车 REA 核验](hellobike-return-analysis.md)确认了官方调度费场景、费用接受参数、蓝牙读写和反馈上报流程，并记录原生两套还车状态模型的差异。该补证提供后续接入依据；本版本仍按上述范围处理。

## 付款与结清

范围仅为平台实际返回且可用的普通支付宝 `001`、哈啰余额 `003` 和普通银联 `1201`。微信 SDK、免密、开卡、签约、骑行卡和复杂组合支付交由哈啰处理。余额沿用官方判断：有balanceEnough时使用该值，缺失时比较accountBalance与应付金额；展示官方balanceText。服务端enableSelect=false仍禁选；普通渠道不再误用只适用于全余额013的绑卡／余额引导标记。签约条件按官方字段组合判断，原文说明完整保留。

支付前重新读取原订单费用及渠道，核对付款标识、金额和条件，再可靠保存付款尝试后发送一次请求。付款组件返回的渠道为准：在共用桥接边界将支付宝映射至已有 `13`、银联映射至已有 `52`；不把 rideGuid 当付款 guid，也不机械地把 tradeId 当 orderId。

SDK 回跳、HTTP 成功和付款组件的状态不直接标记付款成功。原订单查询采用首次加最多三次重查、间隔三秒；仅匹配 guid、金额及业务身份且数值 `payStatus == 1` 确认该付款。未知结果保留原付款记录与查询入口，不允许创建另一笔付款。

付款确认与骑行费用结清分开处理：

- 业务费用状态 `SUCCESS` 才将骑行标记为已结清；`CLOSED` 显示订单已关闭。
- 通用付款已确认、但业务费用读取失败或仍未结清时，可显示付款已确认，骑行费用仍为待确认，保留入口继续核对。
- 待付项目全部出现 `SUCCESS`、缺少业务状态、空列表或 SDK 返回成功均不单独推断骑行已结清。

## 保存、恢复与账户隔离

哈啰使用独立的 Android Keystore／AES-GCM 命名空间。凭据、地区、原账户身份、骑行记录和付款尝试在一个经过检查的原子记录中保存。待提交记录写入失败时停止发送开锁、关锁或付款请求；保存成功后即使协程取消，磁盘与内存仍共同保留该次记录。

三个生活服务平台退出规则一致：先取消并等待所选平台的任务，再完全清除该平台的本地凭据、全部订单、历史保留记录及当前展示，包括未结束、未结清和结果未知记录。同账号重新登录不从本机恢复这些记录。退出不发送还车、取消订单或解约请求；其他平台和校园卡不受影响。

换账号成功的保存与内存发布在同一持久化锁下完成；提交期间取消不能造成磁盘新账号、内存旧账号。新凭据保存失败时保留原账户及记录。核验使用现有 `LifeAccountVerifier`，过期凭据清除后保留脱敏手机号和恢复记录；网络或不完整数据保留凭据并显示检查失败及具体原因。

若发现原加密记录存在但无法读取，重建存储时持久保存「请核对原订单」提醒。用户可在哈啰核对后确认提醒；确认不代表任何车辆结束或费用结清。前台恢复仅查询服务器与已知原订单，不补发命令或重新唤起原支付。首次安装尚无地区时也能保存并恢复服务器返回的骑行；地区保持缺省，实际还车时重新定位、反查并保存有效地区，不弹出地区设置。
