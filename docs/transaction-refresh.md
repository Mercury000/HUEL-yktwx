# 交易后的余额、账单与统计刷新

充值／缴费订单成功与余额、账单搜索、统计接口的更新时间可能不同。旧实现只失效一次缓存并读取一轮；一轮成功但内容仍旧的响应会重新获得 60 秒缓存有效期。本次补充只读查询的有限补查与待刷新状态，不改变支付结果判据。

## 触发与范围

- 本人充值成功使余额、账单、月度收支及收入图表失效；代人充值保留未知收支方向。
- 付款码确认扣款使账单、月度收支及支出图表失效；已取得的余额不重复查询。
- 普通取码、手动余额查询、回前台查询取得同账号同账户的新余额时，也通知账单与月度收支失效。首次有效网络读取、本地缓存恢复、账号或付款账户切换不计算余额变化；余额变化通知不展示交易成功反馈。
- 缴费成功增加所属项目信息；宿舍补查只读取受影响项目及配对表必须的配置。

## 缓存与补查

- 正常读取继续复用 60 秒缓存。失效后的读取与本轮开始前的有效网络快照按查询键比较，列表、收支、笔数、趋势、分类、排行分别跟踪。
- 成功返回相同内容不会解除待刷新状态；内容变化只表示该数据观察到了更新，不证明某笔交易已经入账。
- 没有原网络基线时，第一份响应先建立比较基线，保守地保持待刷新。
- 查询可见页面的数据。充值结果弹窗关闭后再执行相关读取；离开页面、覆盖弹窗、切后台或离线时暂停补查，保留状态与已用预算。
- 一次初始查询后最多补查三次，分别在上一轮结束后等待 2、5、10 秒；后续补查静默进行，只查询尚未观察到更新或读取失败的部分。未查询部分保留原有错误，失败不会重新获得缓存有效期。
- 手动刷新取消同一数据的排队补查，并与在途请求合并；返回页面不重置补查预算。
- 预算用完只停止定时请求。待刷新数据下次进入仍需联网，缓存只用于先展示；不通过固定超时把旧响应重新标记为新鲜。
- 新事件撤销旧读取版本；被取消或迟到的响应不能确认新一轮更新。退出／切换账号清理比较基线与定时任务。

保守策略的代价是：合法但一直不变的查询结果（例如筛选不包含新交易或排行未变化）可能持续在进入时联网一次。自动补查仍有上限，不做无限轮询；日期不包含当前交易、收支方向不相关的图表不启动补查。

## 状态与职责

- `TransactionRefresh` 按查询键集中保存网络快照、比较基线、是否观察到更新及最近读取是否失败。`needsRead` 统一决定补查范围；读取失败不会撤销已观察到的更新，只有实际成功响应才能清除失败状态。未查询的接口保留状态，旧请求不能改变新一轮状态。
- `cacheReadAt` 统一处理单接口读取时间：受交易影响且尚未更新、或读取失败的数据不能获得新鲜缓存时间；不相关日期的成功读取仍可正常复用。页面继续负责多接口的整体完成状态和缓存快照。
- ViewModel 负责各自的查询范围、分页、项目配置及界面错误文案；错误文案的清除不再作为接口已恢复的判据。
- 只读失败额外保存 `ReadFailureKind`，网络恢复、提示格式与合并均按异常类别判断，文案不参与分类。成功读取、查询切换及账号重置同步清除对应类别；局部补查保留未查询区域的类别，电表合并和旧读数保留也继续携带类别。展示动画和重试快照同时保留文案与类别；网络提示合并时仍单独展示业务错误，未标注类别的错误按普通失败展示。
- 账单、宿舍和“我的”页面只展示状态并转发用户操作，不在组件内部自动激活读取；界面壳通过可读取页面状态统一激活。离线切换页面不会绕过这一入口，恢复连接后再读取。离线未读取区域展示临时网络提示，保留已有数据；提示只属于显示状态，不写入 ViewModel 或缓存，也不在恢复连接后继续保留为首读失败。
- 付款、余额／卡状态、账单明细／统计、大厅和个人资料由界面壳统一发布同一份 `ReadEnvironment`（可读取页面、前台、网络快照、连接世代及付款／账户可见性）。各 ViewModel 的 `ReadController` 集中管理查询预留、网络租约、普通重试、取消和完成后的再次判断；内部 `ReadGate` 负责许可和失败预算。普通自动网络读取每个查询、每个连接世代最多连续失败两次，首轮失败后等待 600 毫秒补试一次，成功清空预算；激活不绕过退避，手动触发重置预算。重连只补试本世代尚未真正开始的网络失败，在途请求结束后按当前环境和查询新鲜度判断。真实网络尝试在本地准备完成后记录，取消或替换同时清除任务、待执行操作及计时器；迟到完成不能释放新请求的租约。交易补查使用 `Transaction` 触发，继续由 `TransactionRefresh` 管理 2／5／10 秒和三次上限，不叠加普通网络重试。详见 [展示读取调度](read-scheduling.md)。
- 本地准备与网络任务分别管理：网络失效不撤销同账号的本地缓存准备；缓存尚未确定时不生成离线首读错误。付款码仍按原有有效期失效，离线或被弹层覆盖时不发起新的取码，到期清除旧码并在页面可读取后重新核验。离线下拉仅提示网络不可用，保留现有内容和真实请求错误。
- `TransactionReadCoordinator` 统一校验事件所属账号并分发失效与激活操作。应用界面提供最新账号和可读取的可见页面；页面不可读取时只失效，待可见后执行读取。余额变化只更新账单和月度指标，已取得的新余额不重复读取。

## 验证

`TransactionRefreshTest` 使用虚拟时间验证退避、预算、隐藏／返回、手动请求合并、账号清理、读取版本、失败与更新状态的独立性及缓存时间规则。

`TransactionDataRefreshTest` 使用虚构服务验证余额变化事件、独立延迟、超出补查预算、同一缓存窗口内返回、迟到响应、月度指标选择性刷新、项目与收支图表范围。

`TransactionNavigationTest` 通过实际应用页面与按钮验证完成／返回关闭、余额先更新而账单随后更新，以及回到“我的”刷新月度收支。全部回归不连接真实支付接口，也不要求实际消费或充值。

`TransactionReadCoordinatorTest` 独立验证旧账号事件隔离、不可见页面延迟读取、缴费项目范围及余额变化事件的激活范围。
