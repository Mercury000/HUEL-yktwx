# 应用更新检测

设置页提供默认开启的“自动检查更新”开关及唯一的手动“检查更新”入口，当前版本号显示在入口右侧。关于页仅保留顶部版本信息，不重复展示检查入口或版本号。开关持久保存在本机，不随退出登录重置，关闭自动检查后仍可手动查询。

同意《使用须知与隐私说明》且应用处于前台后，在独立协程中检查更新；无需先登录，登录失败不取消更新请求，登录页与主页面切换也不重复请求。未同意时不请求更新服务，也不展示缓存的更新提醒。同一安装版本成功检查后间隔 24 小时，失败后间隔 1 小时，冷却结束后在下次进入前台时重试，不设置后台定时重试。成功包括没有新版本、没有已发布版本或没有兼容版本的有效响应。检查完成时记录对应间隔，跨重启保留；冷却期间返回前台或重建 Activity 不重复请求。请求开始先记录 1 小时冷却，取消或失效请求的迟到响应不覆盖记录；旧版仅有检查时间的记录按 24 小时间隔兼容。安装版本变化后重新检查。手动查询绕过频率限制；已有请求时共用本次结果，不并发重复检查。界面预览不访问更新服务。

自动检查没有全页加载、失败提示或自动弹窗；发现新版本后，在付款、大厅、账单、我的四个主 tab 统一显示内联更新提示。位置均为顶栏下方的内容最上方，在付款码卡片、大厅服务、账单明细／统计切换区或个人信息之前；顶栏下间距为 10dp，左右边距为 16dp，下方间距为 12dp。设置和关于页不放置提示条，设置仍保留自动检查开关和手动检查入口。提示条沿用内联反馈的圆角、间距和出现动画，使用淡主题色背景、小更新图标与普通正文色；整条正文可点击，右侧仅保留低对比度的关闭图标，没有独立的“查看”按钮。文字最多两行，关闭图标为 14dp，触控区域为 44dp。提示条随内容滚动，不悬浮遮挡，也不等待充值、缴费、卡片操作或页面动画结束。

登录页复用同一提示条，放在学校名称下方、学号／工号输入框上方，下方间距为 18dp；提示隐藏后不保留空位，展示和关闭不会清空已输入的登录信息。隐私说明的入口与确认流程保持原位。

登录页与四个主 tab 共享发现的版本及关闭状态，任一处关闭后同步隐藏，同一版本至少 24 小时内不再自动提醒；不同版本不受前一次关闭影响。已发现的版本信息按包名、渠道与安装版本缓存，重启后在检查冷却期内仍可显示；检查失败保留已知更新，有效响应确认没有更新时清除缓存。关闭自动检查取消未完成的自动请求并隐藏提示条，重新开启后可恢复尚未被关闭的已知更新；预览与未同意隐私说明的界面不显示提醒。取消、撤回同意或离开前台后的迟到响应不会恢复弹层。

只有点按提示条正文或手动检查发现新版本时，才展示紧凑的 miuix 更新详情弹窗。标题合并版本号，例如“发现新版本 1.2.0”，不单独显示版本 summary；正文使用后端原样返回的更新说明，长内容在限高区域内滚动，底部保留“稍后”与“前往下载”。关闭详情不会隐藏提示条；手动查询绕过提示条的 24 小时关闭限制。登录页与主页面切换时关闭详情，主页面详情离开四个主 tab 或设置页时关闭。

检查入口使用 miuix `BasicComponent`，标题始终为“检查更新”，右侧显示 `BuildConfig.VERSION_NAME`，不使用 summary 或表示进入下一页的箭头。手动检查期间仅在右侧显示转圈并禁用重复点击，标题和位置保持不变；有更新时弹窗，无更新、无已发布版本或无兼容版本时用 Toast 提示；网络异常与其他失败也用 Toast，页面不保留失败文案。自动查询失败不显示 Toast、弹窗或加载提示。

## 使用须知与隐私说明

须知以简短段落告知问题修复、功能改进等更新用途，服务地址 `https://cxt.303889.xyz`，发送的包名、当前版本、Android 系统 API 级别及发布渠道，以及服务可获得来源 IP 地址；明确请求不携带一卡通账号、密码、登录令牌或设备唯一标识，自动检查可关闭且关闭后仍可手动检查。不对未经核实的服务端日志保存情况作出承诺。开源介绍说明用户可自行审阅源代码或开展安全审计。

正文变化会通过现有 SHA-256 同意记录机制要求用户重新阅读并同意，清理旧登录凭据与业务展示缓存后等待主动登录。现有正文已说明更新服务及发送数据，并未限定登录后检查；登录页更新提示不修改正文或同意记录，只将检查条件设为已同意隐私说明。

## 接口

源站为 `https://cxt.303889.xyz`，调用：

```text
GET /v1/app/check?packageName=<applicationId>&versionCode=<versionCode>&sdkInt=<SDK_INT>&channel=<stable|preview>
```

依据用户提供的 OpenAPI 3.1.0 文档（服务版本 `0.4.0`）及本地后端实现，接口已取消 `abi` 参数。发布渠道由 GitHub Release 的 `prerelease` 标记决定：普通 Release 对应 `stable`（正式版），标记为 Pre-release 的 Release 对应 `preview`（预发布版）。`all` 仅用于版本列表的全部渠道筛选，`/v1/app/check` 不接受 `all`。

客户端目前统一查询 `stable`，没有预发布渠道选择；Android 的 `preview` 构建用于 UI 预览，不据此选择 GitHub 预发布渠道。请求使用当前安装包自身的包名和版本，UI 预览模式不访问更新服务。后端预发布版本仍使用通过包名、签名和非 debuggable 校验的发布 APK。参数仅包含包名、安装版本、Android API 级别和发布通道；不携带账号、密码、Token、付款码、设备唯一标识或学校业务请求头。

响应使用 `schemaVersion=1`、`updateAvailable`、`reason` 和 `latest`。当前已核对的 reason 为 `updateAvailable`、`currentOrNewer`、`noPublishedRelease`、`noCompatibleRelease`。`latest` 可为空；有更新时按 `AppRelease` 读取必填的 `versionCode`、`versionName`、`notes` 和 `downloadPageUrl`，其余发布元数据与 `assets` 不参与客户端判断。即使无更新时 `latest` 返回完整发布信息，也不触发更新弹窗。更新判断及通道、系统版本和安装包兼容性由后端负责，客户端直接使用 `updateAvailable` 与 `reason`，不重复筛选安装包或比较版本；版本号仅用于展示及避免重复自动提示。更新说明原样显示，不解析或过滤提交记录。字段缺失、无法解析或更新标记与 reason 不一致的响应按检查失败处理。

更新检测使用独立 HTTPS 连接，连接与读取超时均为 10 秒，不跟随接口重定向，不关闭 TLS 校验，响应上限 256 KiB。点按“前往下载”通过浏览器原样打开后端必填的 `latest.downloadPageUrl`，客户端不改写或替换地址，由发布服务维护下载页面地址。应用不后台下载、不自行安装、不申请安装未知应用或存储权限；下载页面处理安装包选择，Android 安装器处理包签名和安装。

`2026-11-01` 按新版接口不传 `abi` 核对：正式最新版为 `1.1.0 / versionCode=3`；本地版本 3 返回 `currentOrNewer`，模拟版本 2 返回 `updateAvailable`，两者的 `latest` 均包含完整 `AppRelease` 信息。实现和定向测试依据服务 `0.4.0` 的 OpenAPI schema 及这两次公开响应；未执行 APK 下载或安装。
