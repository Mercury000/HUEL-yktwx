# 玻璃材质对比度检查

检查日期：2026-11-16。范围为当前 `app/src/main` 中所有玻璃入口、业务弹层调用和依赖的共用控件。检索覆盖了 29 个业务弹层调用位置、共用弹层构造器，以及顶栏、菜单、标签、OS4/iOS 底栏和服务小岛的直接材质路径。

## 结论与修改

筛选交易类型原先直接使用普通页面的 `surfaceContainerHigh` / `secondaryVariant`，没有采用充值金额按钮已经使用的玻璃配色。现在其启用、选中与禁用配色都来自相同的 `GlassDialogButtonDefaults`，保留胶囊形状、间距和按压反馈。

检查中发现的问题及统一处理：

| 路径 | 原问题 | 处理 |
| --- | --- | --- |
| 筛选交易类型 | 未选中项使用普通不透明卡片底色 | 与充值金额按钮共用普通/主要玻璃配色 |
| 房间、表类型及支付方式标签 | 未选中项用普通说明文字色，没有对齐玻璃按钮文字配色 | 弹层内统一采用充值普通按钮的文字配色，包括无有效选中项的分支 |
| 下拉当前值及箭头 | 仍使用低透明度的操作文字色 | 共用玻璃弹层主题提升操作文字；无可用选项时按实际禁用状态显示 |
| 输入提示、说明文字、对话框摘要 | 默认提示和说明色依赖普通背景；嵌套卡片使对比度进一步下降 | 弹层内统一覆盖 `onSecondaryContainer`、`onSurfaceVariantSummary`、`onSurfaceVariantActions`；默认对话框摘要同步处理 |
| 生活服务帮助文字 | 浅色 `DashboardPalette.muted` 是固定浅灰，绕过主题说明色 | 在玻璃弹层中使用统一说明色，覆盖接水、淋浴、洗衣、哈啰帮助及登录说明 |
| 购买/续费小按钮 | 自定义的默认蓝色文字与浅蓝填充绕过普通玻璃按钮映射 | 仅默认小按钮配色对齐玻璃普通按钮；调用方明确指定的颜色保留 |
| 收款人、房间、电表、出水选项、设备提供商、重选支付方式 | 共用选择卡自行维护填充、文字和禁用参数 | 启用、选中、禁用统一复用充值按钮配色；保留边框和选中动画 |
| 输入框、标签底板、内嵌中性卡片 | 半透明底色单独维护，与按钮存在细小差异 | `glassControlFill()` 直接使用官方普通玻璃按钮填充 |
| 日期滚轮 | 未选中项使用主色再降低透明度 | 玻璃弹层采用普通按钮文字色作为未选中基础色；保留滚动缩放、边缘渐隐及选中主色 |
| iOS/OS4 服务小岛 | 副文案和关闭图标使用普通页面浅灰色；OS4 默认折射明暗处理使深色底板过度提亮 | 玻璃材质使用普通玻璃按钮文字色；OS4 按原生导航栏设置 `shading = false`；普通底栏路径保留原颜色 |
| 缴费电表类型标签 | 调用方只拦截回调，未向标签传入禁用状态 | 转发 `enabled`，使文字和操作状态一致 |

`OverlayAppearanceContent` 在共用弹窗和底部弹层内部提供上述语义颜色。切换玻璃开关始终保留同一个内容调用位置，并保留现有按压反馈。该处理覆盖依赖这些语义颜色的原生组件及项目控件，而无需在每个页面复制配色分支。

## 验证

- 修复前渲染测试复现筛选与充值的普通按钮底色不一致。对比度取色使用文字内空白边距或紧邻文字的空白位置，避免把抗锯齿字形边缘当作底色；最初使用文字左上角所得的约 3.82∶1 不作为最终测量结果。
- 新渲染检查覆盖浅色、深色、Monet 浅色和 Monet 深色。筛选与充值实际填充比较一致；普通选项、房间卡、购买按钮、下拉当前值、空输入提示和说明文字按实际渲染背景检查至少 4.5∶1。选中主要按钮继续采用充值参照的官方主色配色。
- 交互检查覆盖选择、无选中项、禁用、外观切换、打开菜单恢复、支付草稿/选择保留、日期滚轮边界和服务小岛材质切换。
- 共 10 个直接相关的测试通过。新增渲染检查包括筛选/充值的 4 种主题、弹层控件的 8 种主题与选择状态组合，以及小岛的 16 种主题、iOS/OS4 与模糊开关组合，共 28 个渲染组合。修正 OS4 明暗处理后，小岛的全部 16 种组合及原材质切换测试通过。
- 验证使用 API 35 的本地原生渲染测试及截图审阅；当前没有连接 Android 设备，因此未记录真机验证结果。

这里的完整范围是当前仓库内的全部玻璃调用及配色分支。渲染检查以共用组件覆盖其调用页面，不等同于每个业务页面、每种真实背景和每台设备都逐屏拍照。
