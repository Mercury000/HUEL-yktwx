# 更新检查行为与验证

stable 订阅检查正式版；beta 订阅并发检查正式版和测试版。版本选择使用整数 `versionCode`，签名策略使用单调递增的 `policyRevision`。

## 返回条件

单请求上限为 10 秒；一个来源连续读取指针和清单，首个有效来源等待上限为 21 秒；整个检查上限为 22 秒。时间上限不代表固定等待。

首个来源完成签名、摘要、渠道、身份和有效期校验后保留 300ms 收敛窗口，权威响应优先，镜像回退选择签名有效的最高策略编号并拒绝同编号冲突。来源收敛可以跨过首个来源等待期限，渠道等待留出相应余量。

首个渠道得到有效清单后最多再收集另一个渠道 300ms，再取消未完成请求。来源或渠道全部结束时立即返回。取消传递到网络调用，检查不等待阻塞的读取线程。

## 结果与缓存

| 情况 | 结果 |
| --- | --- |
| Contents API 的 latest 指针返回 404 | 确认暂无已发布版本 |
| 官方 Raw 的 latest 指针返回 404，窗口内没有有效 Contents API 清单 | 确认暂无已发布版本 |
| Raw 404，Contents API 的有效清单在窗口内返回 | 采用 Contents API 清单 |
| 普通 CDN 404 或不可变清单文件 404 | 单独不能确认未发布 |
| 一渠道有有效新版本，另一渠道未完成 | 返回新版本，仅更新已完成渠道缓存 |
| 一渠道无新版本，另一渠道未完成 | 提示具体未完成渠道，不宣称整体最新版 |
| 未完成渠道已有更高的已知更新 | 保留已知更新，不用较低版本替换，不自动打开旧详情 |
| 无可信清单且收到 HTTP 403/503 等服务错误 | 提示更新服务暂时不可用 |
| I/O 错误或超时 | 提示网络错误 |
| 过期、策略编号或版本回退 | 提示更新信息已过期，保留已接受策略 |
| 同编号内容不同或强制边界回退 | 提示更新信息暂时不一致，保留强制要求 |
| 签名、格式或身份校验无效 | 提示更新信息校验未通过 |

完整成功后自动检查冷却 24 小时；失败或部分渠道未完成时冷却 1 小时，即使已找到另一渠道的新版本也保留重试机会。手动检查绕过冷却，并与自动检查共享活动会话。自动结果保持静默，手动结果给出明确反馈。

发布必须保留已接受策略的单调性。历史指针或不可变清单丢失后不能重新从低编号发布；客户端不会通过清除记录或降低强制边界接受回退。

## 验证场景

定向测试覆盖官方 404 与服务拒绝、有效 beta 与阻塞 stable、窗口内迟到的较高正式版、来源收敛跨期限、部分结果反馈和缓存、每小时重试、手动加入自动会话、渠道切换取消、慢指针与慢清单、签名冲突、防回退与强制状态保留。

计时从检查调用前开始，到返回结果结束。阻塞来源在返回时仍未释放，并验证请求取消，确认有效结果不会等待慢来源。来源日志记录渠道、主机、指针/清单阶段、耗时与 HTTP 状态或拒绝类别；检查日志记录总耗时与已完成渠道，不记录响应正文、账户或设备标识。

本地计时测试用于验证返回条件，实际联网速度取决于设备和来源响应。真实 APK 发布、CDN 下载与系统安装分别按对应验收流程核对。
