# 生活服务本机策略核对

核对范围：胖乖下单、支付、进度恢复、两平台账户管理及798用水启动。按行为整理为9类，不按错误提示或异常捕获代码的数量计数。此清单不声称所有实现与官方软件一致。

## 本次移除的4类操作限制

| 行为 | 原实现 | 本次处理 |
| --- | --- | --- |
| 退出账户 | 本机有活动或结果未知进度就拒绝退出 | 退出不检查服务状态，停止本机处理并清理所选平台凭据及进度 |
| 更换账户 | 本机有活动进度就拒绝换号 | 去掉服务状态检查，只在请求提交或凭据写入期间避免并发替换 |
| × 移除异常进度 | 无订单号的未知下单记录只标记隐藏，继续持久保存 | 删除指定进度及本机记录；登录失效后也可删除；恢复时清理旧版本已隐藏记录 |
| 同设备重新下单 | 无订单号的历史未知记录永久拦截同设备新订单 | 去掉该拦截，重新扫码后由用户明确发起新订单 |

这4类限制是本项目自行加入，没有核定官方对应规则。官方下单方法及异常分支的REA证据不能用来证明本项目的隐藏记录或长期拦截策略。已取得订单号的待付款订单仍从原订单继续付款。

## 其余5类项目策略

| 行为 | 当前实现 | 依据与覆盖范围 |
| --- | --- | --- |
| SDK等待期限 | 支付宝未进入付款页面等待15秒；返回桥接页后给回调1秒；银联也有15秒唤起等待 | 为修复SDK无回调导致界面无法操作而加入；具体期限为项目选择，未证明官方使用相同值 |
| 查询次数与设备等待上限 | 支付结果最多3次、间隔5秒；胖乖用水等待20次、间隔1.5秒；洗衣启动等待30次、间隔1秒；798等待10次、间隔3秒 | 次数和上限是项目策略。洗衣设备检查40次、间隔500毫秒已另按官方流程核对；其他上限不宣称与官方相同 |
| 账户核验缓存 | 成功结果复用5分钟；自动失败重试冷却30秒；手动刷新绕过缓存 | 项目缓存策略，未核定官方使用相同期限 |
| 冷启动进度恢复 | 胖乖用水仅恢复本机保存且服务端订单匹配的运行进度；核对失败的旧用水记录丢弃；未隐藏的未知洗衣创建记录仍可恢复并允许 × 删除 | 项目恢复策略。没有订单号的洗衣记录不能据此查询平台订单，也不再限制新下单或账户操作 |
| 798新用水限制 | 本机已有活动用水进度时拒绝启动另一台设备 | 项目加入的限制，未核定798官方是否同样限制；本次未改该启动路径 |

服务端设备占用、支持渠道、订单状态等实际响应与上述本机策略分别核对。次日03:00的洗衣完成提醒期限为用户明确指定。订单号及账号匹配、取消请求后的迟到响应隔离用于将结果归属到原操作；它们不提供平台签约、付款或服务完成的结论。
