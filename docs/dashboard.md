# 个人主页与宿舍概览

## 2026-10-26 只读核验

登录后的个人资料由 `GET /berserker-base/user` 返回，通过 `synjones-auth: bearer ...` 鉴权。应用只读取 `name`、`sno`、`departmentName`、`professionName`、`avatar`、`mobile`，不保留完整响应。此接口中 `professionName` 为空，不能作为官方首页专业的唯一来源。

追加只读核验确认 `GET /berserker-app/cardStyle?synAccessSource=h5` 返回每张卡的 `model` JSON 数组。`textInfoCom` 文字元素的 `prop.code` 为 `name`、`sno`、`thirdLevelDepartment`、`fourthLevelDepartment`，已解析的信息值位于 `prop.value`；后两项分别与用户提供的书院、专业匹配。原生只提取这四个信息值，不渲染模板、不请求卡背景图片；按学工号匹配当前资料，多张卡出现互相矛盾的信息时不任意选取。第三／四级部门的原始字段与个人信息详情中的部门／专业字段保持独立。

官方 `/plat/js/profile.c168ab26.js` 的个人信息页面依次展示头像、学工号、姓名、手机号及非空部门，没有专业行。公开 `GET /berserker-app/frontInfo?synAccessSource=h5` 配置返回 `smsVercode=0`、`disallowPhoneChange=1`，没有 `emailVercode`；因此不显示邮箱或绑定修改入口。银行信息受额外路由参数控制，特殊学校有效期字段在本站未启用。原生详情使用当前官方页面字段集合，不增加接口中其他字段，资料通过下拉刷新，移除同步说明。

核验头像为学校同源 `/minio/` PNG，可无 Token、Cookie 读取。原生只接受同源 HTTPS、无查询参数与路径转义的 `/minio/` 图片路径；不跟随重定向、不发送登录凭证、不使用磁盘缓存，最多读取 2 MiB。加载失败保留占位头像。

郑东电费（410）和文北电费（409）复用已有配置、绑定及级联查询。核验的 410 绑定位于空调电表，409 没有绑定。同一楼层选项中，照明／空调按删除名称末尾的对应后缀后完全相同来配对；它们可共享同一个 `account`，实际缴费目标由各自 `room` 及完整层级选项决定，不按账户 ID 区分或猜测房间 ID。出现同类重名时只保留已绑定电表，并提示用户核实。

已观察电量展示为 `map.showData.信息` 中的“当前剩余电量为…度”，未返回可展示的钱数。宿舍卡显示电量与度数，未知格式保留官方展示文本；单个电表查询失败不伪造读数。打开照明或空调缴费只核验并恢复对应选项，不调用绑定写入；保存／解绑继续由用户在原有房间管理中明确操作。

## 状态与预览

个人资料、本月摘要和宿舍读数仅在内存中缓存 60 秒。账号变更时取消任务并清空页面；旧账号迟到响应不能写入新账号。跨月重新加载本月摘要，读取失败显示重试入口；宿舍刷新失败保留旧读数并标记更新失败。

本次核验只读取官网信息与查询结果，没有下单、支付或修改绑定。预览和自动测试使用虚构姓名、学工号、字母房间选项与电表 ID；截图不使用真实头像或真实账户资料。

宿舍卡的照明／空调缴费直接打开金额弹层，沿用卡片充值的金额组件。房间与电表类型使用代人充值同款选择卡，从宿舍按钮进入时默认选中；取消选择后不能提交金额。弹层出现前核验对应电表完整选项、查询数据和可缴费状态；不跳转房间选择页、不保存或更换官方绑定。用户确认金额后创建订单，再展示该订单返回的支付方式，复用已有支付密码、微信唤起、查单和失败处理。管理入口仍进入完整缴费与房间管理页。

所有支付弹层统一挂在导航层之上的 Scaffold，账户详情充值也能显示和接收输入。账单搜索使用 miuix 默认背景色；触摸搜索框外、滚动列表、切到统计或其他标签、提交搜索时清除焦点并收起键盘。
