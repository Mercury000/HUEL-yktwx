# 个人主页与宿舍概览

## 2026-10-26 只读核验

登录后的个人资料由 `GET /berserker-base/user` 返回，通过 `synjones-auth: bearer ...` 鉴权。应用只读取 `name`、`sno`、`departmentName`、`professionName`、`avatar`、`mobile`，不保留完整响应。此接口中 `professionName` 为空，不能作为官方首页专业的唯一来源。

追加只读核验确认 `GET /berserker-app/cardStyle?synAccessSource=h5` 返回每张卡的 `model` JSON 数组。`textInfoCom` 文字元素的 `prop.code` 为 `name`、`sno`、`thirdLevelDepartment`、`fourthLevelDepartment`，已解析的信息值位于 `prop.value`；后两项分别与用户提供的书院、专业匹配。原生只提取这四个信息值，不渲染模板、不请求卡背景图片；按学工号匹配当前资料，多张卡出现互相矛盾的信息时不任意选取。第三／四级部门的原始字段与个人信息详情中的部门／专业字段保持独立。

官方 `/plat/js/profile.c168ab26.js` 的个人信息页面依次展示头像、学工号、姓名、手机号及非空部门，没有专业行。公开 `GET /berserker-app/frontInfo?synAccessSource=h5` 配置返回 `smsVercode=0`、`disallowPhoneChange=1`，没有 `emailVercode`；因此不显示邮箱或绑定修改入口。银行信息受额外路由参数控制，特殊学校有效期字段在本站未启用。原生详情使用当前官方页面字段集合，不增加接口中其他字段，资料通过下拉刷新，移除同步说明。

核验头像为学校同源 `/minio/` PNG，可无 Token、Cookie 读取。原生只接受同源 HTTPS、无查询参数与路径转义的 `/minio/` 图片路径；不跟随重定向、不发送登录凭证、不使用磁盘缓存，最多读取 2 MiB。加载失败保留占位头像。

郑东电费（410）和文北电费（409）复用已有配置、绑定及级联查询。核验的 410 绑定位于空调电表，409 没有绑定。同一楼层选项中，照明／空调按删除名称末尾的对应后缀后完全相同来配对；它们可共享同一个 `account`，实际缴费目标由各自 `room` 及完整层级选项决定，不按账户 ID 区分或猜测房间 ID。出现同类重名时只保留已绑定电表，并提示用户核实。

已观察电量展示为 `map.showData.信息` 中的“当前剩余电量为…度”，未返回可展示的钱数。宿舍卡显示电量与度数，未知格式保留官方展示文本；单个电表查询失败不伪造读数。打开照明或空调缴费只核验并恢复对应选项，不调用绑定写入；保存／解绑继续由用户在原有房间管理中明确操作。

## 状态与预览

个人资料、本月摘要和宿舍读数仅在内存中缓存 60 秒。账号变更时取消任务并清空页面；旧账号迟到响应不能写入新账号。跨月重新加载本月摘要，读取失败显示重试入口；大厅刷新失败时保留房间位置，清除该项目的旧读数并标记更新失败。

本次核验只读取官网信息与查询结果，没有下单、支付或修改绑定。预览和自动测试使用虚构姓名、学工号、字母房间选项与电表 ID；截图不使用真实头像或真实账户资料。

宿舍卡的照明／空调缴费直接打开金额弹层，沿用卡片充值的金额组件。房间与电表类型使用代人充值同款选择卡，从宿舍按钮进入时默认选中；取消选择后不能提交金额。提交前核验对应电表完整选项、查询数据和可缴费状态，不自动保存或更换官方绑定。金额区直接展示支付方式；用户确认后创建订单，并核验该订单实际返回的渠道，预选渠道唯一时准备支付，否则停留在渠道选择步骤。后续复用已有支付密码、微信唤起、查单和失败处理。管理和临时缴费均使用大厅弹层，绑定／替换须明确操作并确认。

大厅选房与生活缴费页共用全宽位置选择控件，校区、楼栋、楼层、房间依次排列。郑东与文北都只在位置下拉中展示物理位置，照明／空调统一放在完整房间下方；文北切换表计时在另一楼栋分支中解析同一房间，确认完整楼栋、楼层、房间 ID 后一次替换，不把分支后缀暴露成两个房间。家属区水／电类型使用同一选择器：切换时保留当前已确认位置，在后台按同一住址解析另一项目的唯一选项，全部成功后一次替换项目和完整 ID；缺失、重复或查询失败时回到原项目和原房间，不展示逐级重选过程，也不提交未确认的目标。进入金额页后位置与类型控件收起，不再提供额外“返回选房”入口；从大厅卡片的具体充值按钮进入时固定项目及房间。新增绑定只提供官方允许绑定的类型。

所有支付弹层统一挂在导航层之上的 Scaffold，账户详情充值也能显示和接收输入。账单搜索使用 miuix 默认背景色；触摸搜索框外、滚动列表、切到统计或其他标签、提交搜索时清除焦点并收起键盘。

2026-10-26 代人充值查询成功后直接在当前弹窗展示金额页，顶部保留返回的全部账户候选并默认选中第一项。大厅水电费、代人充值和卡片充值共用金额区、支付方式和充值按钮组件；代人充值点击充值才交给已有支付流程，查询或默认选中不提交订单。实现和验证边界见 `others-recharge.md` 与 `hall-meter-pairing.md`。

首次读取时，大厅房间、校园网套餐和“我的”资料、月度金额使用与内容等高的占位，未查完不显示“尚未添加房间”。空房间与已绑定房间保持一致的卡片空间，宿舍位置和套餐不预留第二行空白。“我的”资料与月度结果在本次读取完成后一起更新；刷新时保留现有内容及错误提示，读取充值配置时保持按钮文案，避免内容反复撑高或收缩。布局回归比较普通与较大字号、浅色与深色下加载前后的卡片位置。

大厅各缴费项目与校园网并行读取，校园网独立发布结果。房间配置全部确认后按上次选择或校区顺序固定显示目标，已绑定表读数和另一类表配对分别完成后更新，未完成部分保持等高占位，所有房间项目读取完成前不显示未绑定；较快返回的其他房间不抢占展示。“我的”个人资料、月度摘要及收支笔数并行读取，资料返回后再同时获取头像与首页身份信息，本次读取完成后统一发布结果。收支两种笔数请求也并行执行，单项读取失败不取消其他独立数据。60 秒是既有内存缓存新鲜度，没有额外加载延时；本次大厅优化不增加缓存或提前查询。账户仓库只在获取／更新会话时锁住普通查询，网络读取期间释放锁，慢项目不再阻塞其他页面。登录、改密、绑定与支付等不可重放操作继续串行保护；会话失效时共享一次重登，旧响应和已取消查询不能清除新会话或恢复已退出账户的数据。

房间管理恢复原来的卡片选择与解绑入口，解绑仍需确认。切换房间时自动按账号保存上次选择，重新进入大厅或重启应用后恢复；没有记录或绑定目标已解绑／替换时按郑东、文北、家属区、其他项目排序选择。刷新及迟到响应保持当前选择，较快返回的其他房间不抢占展示。选择记录仅修改本地展示偏好，不写官方绑定，只存账号及完整绑定目标的摘要，不保存明文位置。家属区合并房间记录各真实绑定的目标摘要，水、电绑定剩余任一匹配时仍能恢复上次选择。
