# 个人主页与宿舍概览

## 当前实现

大厅通过金额弹层提供水电、校园网及代人充值入口；房间查询和临时缴费不自动修改绑定，保存 / 解绑由用户明确操作。余额、资料、本月概览、账单首屏 / 统计和大厅展示值已有按账号及目标隔离的本地加密缓存，冷启动先恢复展示再联网核对，同一运行中沿用一分钟内存新鲜度。旧值更新为新值时播放共享数字动效，数值不变时不播放。

查单确认充值 / 缴费成功后发布数据失效事件，账单、本月概览和缴费相关的大厅数据在页面可见时刷新；自己的充值及一卡通缴费同时使自己的余额失效，代人充值和微信缴费不重查自己的余额。事件独立于结果弹层的完成按钮、返回键等关闭方式。实验性转回检测直接保留已查到的新余额，同时使账单和本月概览失效。

公开使用与构建说明见 [README](../README.md)，协议和实际验证范围见 [接口说明](api.md)。以下按日期保留核验与开发记录，较早记录中的状态描述以本节及后续更新为准。

## 2026-10-26 只读核验

登录后的个人资料由 `GET /berserker-base/user` 返回，通过 `synjones-auth: bearer ...` 鉴权。应用只读取 `name`、`sno`、`departmentName`、`professionName`、`avatar`、`mobile`，不保留完整响应。此接口中 `professionName` 为空，不能作为官方首页专业的唯一来源。

追加只读核验确认 `GET /berserker-app/cardStyle?synAccessSource=h5` 返回每张卡的 `model` JSON 数组。`textInfoCom` 文字元素的 `prop.code` 为 `name`、`sno`、`thirdLevelDepartment`、`fourthLevelDepartment`，已解析的信息值位于 `prop.value`；后两项分别与用户提供的书院、专业匹配。原生只提取这四个信息值，不渲染模板、不请求卡背景图片；按学工号匹配当前资料，多张卡出现互相矛盾的信息时不任意选取。第三／四级部门的原始字段与个人信息详情中的部门／专业字段保持独立。

官方 `/plat/js/profile.c168ab26.js` 的个人信息页面依次展示头像、学工号、姓名、手机号及非空部门，没有专业行。公开 `GET /berserker-app/frontInfo?synAccessSource=h5` 配置返回 `smsVercode=0`、`disallowPhoneChange=1`，没有 `emailVercode`；因此不显示邮箱或绑定修改入口。银行信息受额外路由参数控制，特殊学校有效期字段在本站未启用。原生详情使用当前官方页面字段集合，不增加接口中其他字段，资料通过下拉刷新，移除同步说明。

核验头像为学校同源 `/minio/` PNG，可无 Token、Cookie 读取。原生只接受同源 HTTPS、无查询参数与路径转义的 `/minio/` 图片路径；不跟随重定向、不发送登录凭证、不使用磁盘缓存，最多读取 2 MiB。加载失败保留占位头像。

郑东电费（410）和文北电费（409）复用已有配置、绑定及级联查询。核验的 410 绑定位于空调电表，409 没有绑定。同一楼层选项中，照明／空调按删除名称末尾的对应后缀后完全相同来配对；它们可共享同一个 `account`，实际缴费目标由各自 `room` 及完整层级选项决定，不按账户 ID 区分或猜测房间 ID。出现同类重名时只保留已绑定电表，并提示用户核实。

已观察电量展示为 `map.showData.信息` 中的“当前剩余电量为…度”，未返回可展示的钱数。宿舍卡显示电量与度数，未知格式保留官方展示文本；单个电表查询失败不伪造读数。打开照明或空调缴费只核验并恢复对应选项，不调用绑定写入；保存／解绑继续由用户在原有房间管理中明确操作。

## 状态与预览

个人资料、本月摘要和宿舍读数仅在内存中缓存 60 秒。账号变更时取消任务并清空页面；旧账号迟到响应不能写入新账号。跨月重新加载本月摘要；读取失败就近提示，通过下拉刷新恢复。大厅刷新失败保留已核实的同一房间、电表读数与校园网数据，首次没有数据时显示读取失败。

本次核验只读取官网信息与查询结果，没有下单、支付或修改绑定。预览和自动测试使用虚构姓名、学工号、字母房间选项与电表 ID；截图不使用真实头像或真实账户资料。

宿舍卡的照明／空调缴费直接打开金额弹层，沿用卡片充值的金额组件。房间与电表类型使用代人充值同款选择卡，从宿舍按钮进入时默认选中；取消选择后不能提交金额。提交前核验对应电表完整选项、查询数据和可缴费状态，不自动保存或更换官方绑定。金额区直接展示支付方式；用户确认后创建订单，并核验该订单实际返回的渠道，预选渠道唯一时准备支付，否则停留在渠道选择步骤。后续复用已有支付密码、微信唤起、查单和失败处理。管理和临时缴费均使用大厅弹层，绑定／替换须明确操作并确认。

大厅选房与生活缴费页共用全宽位置选择控件，校区、楼栋、楼层、房间依次排列。郑东与文北都只在位置下拉中展示物理位置，照明／空调统一放在完整房间下方；文北切换表计时在另一楼栋分支中解析同一房间，确认完整楼栋、楼层、房间 ID 后一次替换，不把分支后缀暴露成两个房间。家属区水／电类型使用同一选择器：切换时保留当前已确认位置，在后台按同一住址解析另一项目的唯一选项，全部成功后一次替换项目和完整 ID；缺失、重复或查询失败时回到原项目和原房间，不展示逐级重选过程，也不提交未确认的目标。进入金额页后位置与类型控件收起，不再提供额外“返回选房”入口；从大厅卡片的具体充值按钮进入时固定项目及房间。新增绑定只提供官方允许绑定的类型。

所有支付弹层统一挂在导航层之上的 Scaffold，账户详情充值也能显示和接收输入。账单搜索使用 miuix 默认背景色；触摸搜索框外、滚动列表、切到统计或其他标签、提交搜索时清除焦点并收起键盘。

2026-10-26 代人充值查询成功后直接在当前弹窗展示金额页，顶部保留返回的全部账户候选并默认选中第一项。大厅水电费、代人充值和卡片充值共用金额区、支付方式和充值按钮组件；代人充值点击充值才交给已有支付流程，查询或默认选中不提交订单。实现和验证边界见 `others-recharge.md` 与 `hall-meter-pairing.md`。

首次读取时，大厅房间、校园网套餐和“我的”资料、月度金额使用与内容等高的占位，未查完不显示“尚未添加房间”。空房间与已绑定房间保持一致的卡片空间，宿舍位置和套餐不预留第二行空白。“我的”资料、首页身份、头像、月度金额和笔数分别完成后更新；刷新时保留现有内容及各区域错误提示，区域读取成功后独立清除对应错误，读取充值配置时保持按钮文案，避免内容反复撑高或收缩。布局回归比较普通与较大字号、浅色与深色下加载前后的卡片位置。

大厅各缴费项目与校园网并行读取，校园网独立发布结果。房间配置全部确认后按上次选择或校区顺序固定显示目标，已绑定表读数和另一类表配对分别完成后更新，首次读取的未完成部分保持等高占位；刷新同一绑定目标时保留配对表原有读数并标记更新中，配对结束后替换结果，所有房间项目读取完成前不显示未绑定；较快返回的其他房间不抢占展示。“我的”个人资料、月度摘要及收支笔数并行读取，资料返回后立即发布并同时获取头像与首页身份信息，两者分别补齐；月度摘要和笔数独立发布，笔数失败只显示笔数区域错误，不使已完成金额回退为骨架。收支两种笔数请求也并行执行，单项读取失败不取消其他独立数据。60 秒是既有内存缓存新鲜度，没有额外加载延时；本次大厅优化不增加缓存或提前查询。账户仓库只在获取／更新会话时锁住普通查询，网络读取期间释放锁，慢项目不再阻塞其他页面。登录、改密、绑定与支付等不可重放操作继续串行保护；会话失效时共享一次重登，旧响应和已取消查询不能清除新会话或恢复已退出账户的数据。

房间管理保留卡片选择与解绑入口，已确认房间可在其他项目仍读取时切换；解绑与新增绑定仍等待当前刷新结束，解绑仍需确认。切换房间时自动按账号保存上次选择，重新进入大厅或重启应用后恢复；没有记录或绑定目标已解绑／替换时按郑东、文北、家属区、其他项目排序选择。刷新及迟到响应保持当前选择，较快返回的其他房间不抢占展示。选择记录仅修改本地展示偏好，不写官方绑定，只存账号及完整绑定目标的摘要，不保存明文位置。家属区合并房间记录各真实绑定的目标摘要，水、电绑定剩余任一匹配时仍能恢复上次选择。

2026-10-26 加载布局调整与查询并行优化后，全量 `:app:testDebugUnitTest` 通过 421 项测试，零失败、错误或跳过；`:app:assembleDebug` 与 `:app:assemblePreview` 均成功。截图及布局位置检查使用虚构数据，未执行真实充值。

## 2026-10-29 失败反馈统一

首次所有远程内容都未取得时，仅在页面壳层内显示一个居中失败图标和一行提示。有效内容（包括成功读到的空结果）出现后，单个板块的网络失败留在对应板块，复用现有单行 InlineError；多个板块网络失败才合并到内容顶部，并写明受影响板块，如“水电费、校园网更新失败，请下拉刷新”。顶部提示连同板块间距以 200ms 展开／收起，提示以 150ms 淡入／淡出；首个内容项保持稳定，消失后不预留空行或间距，退出途中保留原提示文案。水电表归属同一水电费板块，摘要与笔数归属同一概览板块，不按请求数制造多处提示。已取得的数据继续显示，未取得的值保持未知，不当作零值或已确认的空结果。其他局部读取失败仍就近提示，复用 InlineError。付款码区域失败复用已有“付款已暂停”的居中图标与状态文字布局，使用“付款码暂不可用”（卡状态未核实时为“暂时无法确认卡状态”）和单行读取失败说明，保留余额、隐藏旧付款码，不显示内联错误条或新增重试按钮；挂失／冻结说明和解挂动作沿用原样。同一区域不叠加角标、底部浮条或多处错误。四大页面失败态保留真实滚动容器，均可下拉刷新，无额外重试按钮。

页面骨架沿用原内容形状，只延迟绘制 250ms，再以 150ms 淡入；快速失败取消未展示骨架的出场。延迟仅在页面读取过渡内启用，弹窗和抽屉的骨架立即显示，包括共享占位组件；抽屉页面容器明确关闭骨架延迟。首次失败切换使用 150ms 交叉淡化，骨架淡出、失败同时淡入。不延迟请求和结果，不强制骨架停留，不增加全局加载页。付款码仍使用既有专用核验表现。整页失败的重试期间保留失败态，有效内容返回后再切换；并行首屏请求无有效内容时统一汇总，避免逐项错误闪现。

刷新开始清理上一轮读取错误，单板块成功后独立更新对应反馈。顶部已显示的合并错误在当前重试结束前保持原文案与占位；重新激活或下拉刷新后仍是相同错误时，不重复收起／插入，确认没有合并错误后才淡出并收起。重新进入时已有的缓存错误直接展示，避免再次播放入场。大厅、我的及账单重新激活时对失败读取重新尝试，不把失败当成有效缓存。账号、日期或筛选变化仍清理过期数据与合并提示；大厅仅保留相同核实目标的真实读数，不给新房间套用旧值。

登录后的页面壳层统一监听网络恢复与回到前台，只重试当前可见页面的网络读取失败。已有请求进行时合并触发；网络恢复若遇到尚未结束的断网请求，等待其结束，仅在仍失败时补一次读取。弹层覆盖时等页面可见后再处理，重试结果不会自行触发循环。统计页重新激活也会重读失败项目；个人信息详情重新进入时沿用缓存与失败重试规则。连接判断沿用 INTERNET 能力，不以 Android 的公网验证结果阻止校园网访问。

主表读取失败会提前结束副表发现；此时保留同一已核实房间、同一项目的旧副表读数并标记失败，保持上次成功读取时间。新的房间绑定不继承旧房间读数。

## 2026-10-29 使用须知确认

采用用户指定的完整原文，不修改文字或标点，仅分成六段并对非官方性质、账户限制、账号／支付风险、责任、数据传输／存储和持续可用性说明加粗。正文以独立 `UsageNotice` 为唯一来源，登录页采用 miuix 底部弹层及共享标题动效。登录按钮上方保留一行原生 miuix 复选框与正文链接，点击未勾选的复选框或说明行打开全文，已同意时复选框可撤销，链接始终用于阅读。关于页不增加须知入口。

进入登录页不自动打开须知，用户点击协议行或复选框后主动阅读。正文变更用现有系统 Toast 提示“使用须知已更新，请重新阅读并同意后登录。”，旧版本已有凭据但未保存过同意记录时同样用 Toast 提示“登录前需阅读并同意使用须知。”；首次安装及普通退出仅显示未勾选的协议行，不增加解释提示。没有同意时不初始化账号、读取登录记录、自动登录或发起业务请求，已有本地账号／业务状态也不能显示主界面或付款码。首次确认及正文变更后清理旧登录凭据与业务展示缓存，留在登录页等待主动提交，不因同意而自动恢复旧账号。暂时关闭须知后可先输入账号密码及切换显隐，登录按钮保持禁用，键盘提交及登录回调再次检查同意状态；重新打开、关闭须知保留当前输入，初始化清理也保持同一登录表单，密码仍仅在内存中保存。取消、返回、关闭及不同意均不产生同意；正文末尾完整显示后才启用“同意并继续”，滚动本身不代表同意，重新打开从头阅读；全文可以一次完整显示时无需多余滑动。弹层正文可滚动，按钮固定在底部，按实际字号与宽度在左右并排或上下排列间切换，避免窄屏大字号下确认文字换行。
