# 慧生活798用水接入

在现有胖乖流程上接入798：付款页内联登录提醒 → 原生登录抽屉 → 共用扫一扫 → 核对设备 → 开始用水 → 结束用水。未结束的用水可从付款页胶囊岛返回，确认结束后小岛自动消失。

第三方798软件仅用于核定接口、请求头、二维码格式与登录签名。本项目自行实现账号和用水状态管理，复用现有登录容器、扫码页、设备展示、参考计时、操作区及进度胶囊组件，没有搬入第三方业务代码。

## 使用流程

- 胖乖与798账号分别登录、分别加密存储。登录任一平台即可打开付款页唯一的扫一扫入口；识别二维码后进入对应平台。
- 点击付款页798内联提醒打开登录抽屉。输入手机号、图形验证码与短信验证码；图形验证码允许字母，点击图片刷新，不使用独立刷新按钮。发送短信失败后自动换图并清空旧输入，保留错误提示，不自动重发短信；换图失败时可点击验证码区域重试。登录成功留在付款页，等待用户扫码。
- 从扫码页识别798链接但尚未登录时，设备页显示内联登录提醒。登录后恢复该设备查询，不自动启动设备。
- 本会话中重扫同一台已有未结束订单的设备，直接返回原接水进度，不创建新订单或显示通用占用提示。扫描其他设备仍按设备状态查询；占用阻止开始用水时，使用统一的红色错误提示，保留刷新状态，适配浅色和深色模式。
- 启动和结束按钮只发一次命令。本 APP 发起且启动接口已确认接收的新订单，通过专门的状态接口确认运行并绑定用水标记，不依赖设备主页同步返回状态；启动响应丢失时仍需核对使用人。状态查询确认后才显示运行或完成；本次 APP 会话内网络失败保留进度，刷新只查询状态。发送停止命令前再次核对使用人和设备用水标记。
- 离开设备页或退后台不会停止设备，未结束会话保留在付款页胶囊岛，后台暂停查询；返回前台立即核对。确认结束后自动移出岛，当前设备页仍可展示完成详情。
- 杀后台重开后，不直接展示本地旧记录。主页提供账号 ID 和候选设备，结合本地未结束记录逐台核对一次；只有运行状态且使用人匹配本账号时才恢复到岛。已结束、其他使用人的记录不恢复；缺字段、状态未知、请求失败或登录失效时，丢弃无法确认的本地旧跟踪记录，不上岛，不保存待查队列，不自动重试。下次启动仍从服务器主页重新发现当前设备，不累计上次失败的候选。恢复只读，不重发启动或结束命令。
- 本 APP 发起下一次798用水前要求已核对且没有活动会话；服务器发现的本人活动设备分别保留。胖乖接水与洗衣会话独立，洗衣继续保留原有完成记录。
- 页面显示设备状态和本地参考时间。费用、代扣签约、账户绑定与充值请在慧生活798查询或完成。

## 扫码路由

798接受以下明确带平台身份的格式，示例设备编号为虚构值：

```text
https://i.hnkzy.com/q/1/123456789012345
https://cloud.hnkzy.com/h5/?atype=1&id=123456789012345#/pages/app/index
```

手动输入与摄像头使用同一解析入口。手动输入798时填写完整二维码链接；纯数字编号与裸UUID保留原有胖乖含义。拒绝其他域名、HTTP、用户信息、冲突设备字段、重复编号和不支持的路径，避免从任意链接猜取编号。

## 接口核定

通过用户指定的JADX MCP读取当前第三方APK `com.life798.mini`，版本1.4.0、versionCode 20，核定 `WaterApi` 和 `Signer` 的协议。客户端版本与下表请求头的协议版本分别记录。

默认网关为 `https://i.ilife798.com/api/v1`，包含协议、域名与接口路径前缀。请求使用HTTPS、禁用重定向；登录、启动和结束不自动重试。

| 用途 | 请求 | 参数或响应 |
| --- | --- | --- |
| 图形验证码 | GET `/captcha/` | 查询 `s`、`r`；返回图片字节 |
| 发送短信 | POST `/acc/login/code` | JSON：`un`、`authCode`、`s` |
| 登录 | POST `/acc/login?sign=...` | JSON：`authCode`、`un`；Token：`data.al.token`；账号：`data.al.uid` |
| 应用主页 | GET `/ui/app/master` | `ad=true`；账号：`data.account.id`；候选设备：`data.favos[].id/name` |
| 设备主页 | GET `/ui/app/dev/home/1` | `did`、`apply=6`；名称：`data.device.name`；订单标记：`data.device.gene.time`；当前使用人：`data.user.id`；运行与结束随后查状态接口 |
| 设备状态 | GET `/ui/app/dev/status` | `did`、`more=false`；状态：`data.device.gene.status/time` |
| 开始用水 | GET `/dev/start` | `did`、`upgrade=true`、`ptype=91`、`rcp=false` |
| 结束用水 | GET `/dev/end` | `did`、`rcp=false`；不附加登录签名 |

客户端沿用已核定签名协议的固定请求头：`ApplicationType=1,1`、`VersionCode=3.1.9`、`User-Agent=Android_ilife798_3.1.9`。设备查询和控制携带 `Authorization`。提供的官方798 HAR使用 `3.1.10`；这项版本差异没有被证明是查询失败的原因，不据此修改配套的登录与控制协议。

登录签名为 `MD5("authCode=" + 短信码 + "&un=" + 手机号 + 盐值)` 的小写十六进制字符串。盐值参与客户端协议签名，不是用户密码或用水会话标记。

专门的状态接口只接受 `status=1`（运行）和 `status=99`（停止/结算阶段）。设备主页的状态不能套用此规则：新抓包中同一订单在主页显示 `10`，状态接口显示 `1`。归属核对读取设备主页的使用人和订单标记，再查询状态接口确认当前运行与结束；运行时两个接口的订单标记必须相同，避免把旧使用人关联到后续订单。运行必须返回正数 `gene.time`；缺失或未知状态不能当作完成。请求成功 `code=0` 不表示设备已经执行完毕。`-99`、`-21`及HTTP 401/403要求重新登录，其他业务错误保留服务端反馈。

2026-11-05 离线核对两份 11 月 2 日接水 HAR：主动结束前的两次状态查询均相隔约 6.1 秒；启动、结束命令后的首次查询约在 3.1 秒后，结束尚未确认时继续约每 3.1 秒查询。APP 据此采用运行中每 6 秒、启动与结束确认每 3 秒的等待间隔，请求耗时另计。命令后的首次确认也等待 3 秒；确认循环保留约 30 秒的等待上限，超时后仍可在前台继续查询。恢复前台立即核对一次，后台暂停自动轮询。

同日核对新提供的 `798.har`：`/acc/stat.data.al.uid` 与主页 `account.id` 相同，运行设备主页的 `user.id` 也匹配该账号。启动后主页 `favos` 出现正在使用的设备，可用于发现候选；`favos[].owner.id` 不等于该账号，不能当作使用人。普通 `/dev/status` 不提供使用人，因此恢复、返回前台和停止前使用设备主页核对，其余运行轮询使用状态接口。无需签名规则尚未核定的 `/acc/stat`，不读取历史账单判断本次用水。

2026-11-05 核对 `ProxyPin11-5_19_57_43.har`：启动约3.1秒后状态接口返回 `1`；再次进入应用时主页候选设备的 `gene.status=10`，随后设备主页也返回 `10`，但设备主页 `user.id` 匹配本账号，`gene.time` 与全部运行状态查询一致，主动结束后状态接口才变为 `99`。旧实现把设备主页交给只接受 `1/99` 的状态解析器，导致核对报错和重启恢复记录被丢弃；本次改为由专门的状态接口决定生命周期。该抓包没有短信登录请求，不能用于判断登录验签失败原因。另有 `ptype=21`、`cnt=1` 及带签名的启停请求，与此前核定的 `ptype=91` 不同，本次没有据此猜测或改写支付与控制签名。

## 本机配置

沿用仓库既有环境变量或未跟踪的 `local.properties` 注入方式：

| 环境变量 | local.properties | 默认值 |
| --- | --- | --- |
| `HUI798_API_GATEWAY` | `hui798.apiGateway` | 上述网关 |
| `HUI798_SIGN_SALT` | `hui798.signSalt` | 空；缺失时登录提示连接配置缺失 |

本机已填写从接口分析取得的网关与盐值。盐值不写入仓库源码、测试或文档；`local.properties` 和 `tools/` 均由现有规则忽略。构建时通过BuildConfig提供配置，各构建环境需要自行注入。

GitHub Actions构建步骤已从仓库Secrets `HUI798_SIGN_SALT`和 `HUI798_API_GATEWAY`注入盐值与网关。未设置网关Secret时使用Gradle默认值；release缺少盐值直接失败。PR构建不注入接口Secrets，缺配置的debug包可编译但无法登录对应平台。需要在仓库Settings → Secrets and variables → Actions → Secrets中创建这些配置，本机配置不会自动同步到GitHub。

## 实现与验证

- `Hui798Api`：独立798JSON协议与签名。
- `Hui798AccountStore`：复用SecureVault和记录存储接口，使用独立加密命名空间；登录失效保留原账号的记录，换账号不继承记录。
- `Hui798ViewModel`：验证码、短信倒计时、设备识别、启动与结束确认、会话恢复和前台查询。未知启动结果不自动重发或接管无法确认的用水。
- `WaterDevicePage`：胖乖饮用水与798生活用水共用整套设备页，包括居中设备卡、查询与启动等待、参考计时、结束反馈、费用提示、帮助抽屉和固定底部操作区。共用信息卡在各阶段统一显示服务提供方；胖乖的支付宝免密及接水选项作为附加内容嵌入该卡。平台仅传入展示状态、提示与操作回调。
- `Hui798Pages`：共用原生登录容器，将798状态和确认规则映射到共用接水页面；`YktApp`连接统一扫码、平台页面与付款页进度。

定向验证覆盖请求签名与格式、跨平台二维码、验证码刷新竞争、账号隔离、命令重复点击、启动/结束响应丢失、用水标记变化、前后台查询和进度移除。原生界面验证覆盖验证码字母、大字体、明暗主题、用水阶段、798独立进度回调与共用扫一扫；追加胖乖登录、扫码和进度入口的相关回归，不默认运行全量测试、构建或Lint。

以上为本地模拟接口与原生界面验证。尚未发送真实短信、登录或控制实际设备；服务端是否仍接受该签名、目标设备状态变化及 `ptype=91` 适用性仍需本人账号与现场设备联调。
