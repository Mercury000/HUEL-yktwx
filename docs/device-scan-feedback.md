# 扫码设备页的检查、定位与反馈

哈啰单车、慧生活798用水、胖乖接水／淋浴和洗衣设备查询失败后保留设备页及编号。主按钮或内联操作重试时立即给出反馈，同一读取过程不能重复触发；成功后收起提示，再次失败时显示完整原因。

## 共享提示与动画

`AnimatedInlineError`和`InlineRetryFeedback`共用实现。文字与操作共同参与切换，出现、退出、单行变多行及操作变宽导致的换行均由共享组件负责。退出内容没有可执行的旧操作，也不重复暴露无障碍语义。

共享提示通过`ReadLayoutMotion.feedbackTransitions`登记动画。此时`ReadLayout`不挂自己的尺寸动画，直接使用子组件每帧的实测高度。多个提示同时或中途反向变化时，最后一个提示完成后才恢复父层对其他内容的尺寸动画。

页面持有`RetryFeedbackState`，主操作、内联操作及帮助中的读取入口共享即时反馈。即使下一帧前就失败，也显示项目标准短反馈时段并禁止重复点击；不延迟请求，不改变启动、开锁或付款条件。上次失败在读取期间保留，成功后清除。列表有稳定key，状态按账户及设备／记录身份隔离。

## 设备页行为

| 页面 | 检查及反馈 |
| --- | --- |
| 哈啰单车 | 检查、还车校验和重试仅底部主按钮显示转圈。需要定位授权时，内联错误只显示原因，授权／设置只由主按钮提供。 |
| 慧生活798 | 查询开始立即发布读取状态，返回后仍刷新当前设备编号。各读取入口共享反馈，不发送启动／结束用水操作。 |
| 胖乖接水／淋浴 | 查询失败和重试期间保留设备页及编号，读取原设备。主按钮、内联操作与帮助刷新共享反馈。 |
| 胖乖洗衣 | 缺少设备数据时重新读取设备，避免进入空支付表单；设备检查及订单刷新共享主按钮反馈，未知下单结果继续查询已有记录。 |
| 哈啰普通卡 | 获取位置和解析地区使用独立状态。提示显示正在定位／等待授权，其他卡片请求不会延长定位反馈。 |

用水和洗衣的设备检查、启停和订单查询统一由底部主按钮转圈，上方状态卡、洗衣进度区域和内联提示只显示阶段文字或静态图标，避免同一过程重复转圈。用水的启动、结束文字优先于通用检查文字；账号恢复、启停请求返回后的等待阶段及接水结束后的处理仍保留主按钮反馈，失败后恢复原重试入口。确认操作的条件仍由ViewModel决定。

## 定位权限

首次需要定位时请求系统授权，不能根据历史申请或“不显示说明”提前判断只能去设置，这会误判“每次使用前询问”。只有实际拒绝且系统不再提供授权说明后，用户点击才进入本应用设置。设置返回重新读权限；没有当前授权时恢复到可申请状态，粗略位置授权也可继续。

窗口结果按原请求、账户和车辆选择关联。换车、重扫同车、换记录、换账户或已还车后，旧结果不能修改新操作。旧窗口未返回时，新逻辑请求等待旧结果处理后再使用系统启动器。

授权本身不直接发送开锁请求。授权后继续原车辆的官方预骑行，其canSkip仍按官方扫码规则处理，不改变自动确认条件。详见[官方扫码链条](hellobike-scan-chain-rea.md)。

## 定向验证

覆盖独立提示、ReadLayout逐帧高度、操作变宽、同时及中断变化、即时失败、长期读取、成功清理、设备／账户切换、粗略定位、每次使用前询问、设置返回和过期回调；另验证各设备页失败后保留编号、重试原设备、旧响应丢弃以及主操作切换取消旧手势。

日志位于`build/hellobike-card-list-review/`：`final-functional-review.log`、`final-review-followup.log`及`final-official-chain-review.log`。首轮部分测试沿用计费查询作为开锁前置条件、固定轮询延迟，或没有回送按钮修改后的状态；输入已按最终业务链修正，保留原行为断言。
