# 页面与弹层恢复

本项已完成全部页面、弹层与账户切换的实现及主机定向验证。导航栈与业务对象恢复一起交付，使用新 Activity、新 SavedStateHandle、新 ViewModel 和新仓库验证，不以保留原 ViewModel 的配置变化测试代替进程恢复。兼容基线为已发布 1.4.1；未发布的旧页面状态格式直接丢弃。

## 保存边界

`RestorableState` 使用 SavedStateHandle 的保存回调，保存明确的序列化 DTO。每份状态包含格式版本、账户标识和预览标记；业务账户身份未恢复前保留待读取状态，不用初始空值覆盖。身份确认后只消费一次，同账户首次进程恢复可以读取，换号、真实重新登录或预览模式不符时丢弃。

进程内的账户 generation 不写入保存状态。导航额外保存一个界面作用域标识；同一次恢复保留它，真实账户替换则重新生成，使 Compose 的输入、滚动和弹层保存状态一起换代。每份 DTO 的 UTF-8 内容上限为 64 KiB，非法格式或超限内容回退默认页。禁止保存完整 UiState、登录凭据、短信码、支付载荷、头像 Bitmap 或图片字节。

路由使用封闭的 `AppRoute`：静态页面为对象，账单详情携带账单标识和原日期范围，生活设备页携带平台、业务、设备或会话标识及平台账户身份。Miuix 按具体运行时类型注册每一种路由。生活页使用固定内容标识，设备转成订单或选择出水口时只更新参数，不重建整套页面转场。

## 已有验证

`StateRestorationTest` 通过 SavedStateHandle 的实际保存回调、Bundle／Parcel 往返、新 handle、新 ViewModel 和新仓库验证，不复用原业务模型。覆盖等待身份时再次保存、同账户跨进程恢复、换号／重新登录／预览隔离、非法和超限状态、账单详情跨页精确匹配、缺失记录终止及过期结果隔离。

三平台各自的路由恢复测试验证先等账号、匹配原会话、出水口选择、无网络不查新设备、账户不符／ID 失效回退，断言没有启动、停止、短信或付款重放。AvatarViewModelTest 补充图片引用重新解码、裁剪恢复、待返回选图标识、账号隔离和授权失效回退。

当前主机报告位于集成工作区 `app/build/reports/tests/restoration-routes-summary`（8 项）及 `restoration-pages-summary`（21 项），均无失败或跳过；后者包含前者的再次验证，不能相加成不同用例总数。构建日志位于主工作区 `tools/modernization/restoration-routes.log`、`restoration-pages.log`。没有运行 ADB、连接设备任务、全量测试或 Lint。

`restoration-drafts-summary`（16 项）补查账单草稿的 Compose 重建、既有离页关闭规则，以及账单／头像最新的请求隔离修改，全部通过。`BillDraftRestorationUiTest` 保存未提交的金额和日期模式，重建后实际读取输入内容，再点击确认；重建本身不会触发应用筛选或日期选择。
